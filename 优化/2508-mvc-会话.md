## session读取
import(
    contextenhanced "github.com/zsy619/yyhertz/framework/mvc/context"
)
app.InsertFilter("/admin/*", constant.BeforeRouter, FilterSSO)
// FilterSSO 过滤器登录判断
var FilterSSO = func(ctx *contextenhanced.Context) {
    adminId, ok := ctx.Input.Session("adminId").(int64)
}

其中获取到的adminId为0，为什么获取不到已经写入的Session？

```claudeCode

🔍 问题分析

  您在过滤器中获取不到 Session 数据的原因是：每次创建新的 MemoryStore 实例，导致 Session 数据无法持久化。

  关键问题点：

  1. NewMemoryStore 每次都创建新实例：
    - 在 SessionManager.GetSession() 和 SessionManager.CreateSession() 中，每次都调用 NewMemoryStore(sessionID)
    - 这会创建一个全新的空的内存存储，之前存储的数据都丢失了
  2. 没有全局的 Session 存储池：
    - 当前实现中，MemoryStore 的实例没有被保存在任何地方
    - 每次请求都会创建新的 store，无法访问之前请求中设置的数据
  3. 过滤器执行时机：
    - BeforeRouter 过滤器在路由处理之前执行
    - 此时创建的是一个新的 MemoryStore，当然获取不到之前存储的数据
                                                                                  
⏺ User approved Claude's plan:
  ⎿  修复计划：实现全局 Session 存储池

     主要修改：

     1. 在 store.go 中添加全局 Session 存储池：
       - 创建一个全局的 map 来存储所有的 MemoryStore 实例
       - 使用 sync.Map 或带锁的 map 确保并发安全
     2. 修改 NewMemoryStore 函数：
       - 改为 GetOrCreateMemoryStore，先从全局池中查找
       - 如果存在则返回现有的，不存在才创建新的
     3. 在 manager.go 中优化 Session 获取逻辑：
       - 修改 GetOrCreateSession 方法，使用持久化的存储池
     4. 在 session_adapter.go 中修复：
       - 修改 GetSession 和 CreateSession 方法，使用共享的存储池
     5. 添加 Session 清理机制：
       - 实现过期 Session 的自动清理
       - 防止内存泄漏

     具体步骤：

     1. 创建全局 Session 存储池管理器
     2. 修改 MemoryStore 的创建逻辑，使用单例模式
     3. 确保同一个 sessionID 始终返回相同的 store 实例
     4. 添加适当的并发控制和生命周期管理

     这样修改后，无论在控制器中设置的 Session 数据，还是在过滤器中都能正确获取到。
```
