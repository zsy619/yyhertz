## 路由大小写终极解决方案

本系统路由是基于Hertz 使用 Radix 树 来存储和匹配路由。这种数据结构在匹配时通常会区分键的大小写，因此路由匹配也区分大小写。
为了解决大小写匹配问题，我们提供了 `router.case_sensitive` 配置项，用于控制路由匹配是否区分大小写。
对路由进行注册时，可以根据该配置项决定是否同时注册大小写两种形式，防止过多的路由注册，根据常用情况进行分组处理。
1. 路径不大于4个的： 函数 generateVariantsForShortPath
   - 原始大小写路径: /admin/s3/User/GetProfile
   - 小写路径: /admin/s3/user/getprofile
   - 同时匹配：/admin/s3/user/getprofile、/admin/s3/User/GetProfile、/admin/s3/user/getProfile
   - 同时生成蛇形路径：/admin/s3/user/get_profile 全部小写
   - 规则：只处理路径最后两个
2. 路径大于4个的： 函数 generateVariantsForLongPath
   - 原始大小写路径: /admin/s3/User/GetProfile/Details
   - 小写路径: /admin/s3/user/getprofile/details
   - 同时匹配：/admin/s3/user/getprofile/details、/admin/s3/User/GetProfile/Details、/admin/s3/user/getProfile/Details、/admin/s3/user/getprofile/details、/admin/s3/user/getprofile/Details
   - 同时生成蛇形路径：/admin/s3/user/get_profile/details，如果有路径 /admin/s3/User/GetProfile/AddDetail，则生成 /admin/s3/user/get_profile/add_detail
   - 规则：只处理路径最后三个
3. 如果路径包含参数占位符则不处理
    如 /admin/s3/User/GetProfile/:id，则不做任何处理，只要包含 /: 这个模式就不处理。
